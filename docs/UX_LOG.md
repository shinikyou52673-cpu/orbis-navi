# 使い勝手の改善記録

改善メモ・走行記録から見つけた問題と、その対応の要約です。
位置や時刻などの個人の移動情報は書きません（地名は区レベルまで）。

## 2026-11-09
- 利用者の試走での指摘：音楽が止まる／再検索がUターン指示／逆走しても案内が進む／ルートが微妙
  - 前の3つは対応済み（CHANGELOG参照）
  - ルートの質は、走行記録が届いてから分析します

## 2026-11-11
- 利用者の指摘：インカム（声でメモ）が使えず、画面から手入力したメモも送信先に届いていなかった
  - 送信先に届いていたのは、前日の送信テスト1件だけ
- 原因（コードから判明）
  - 送信に失敗すると、次にアプリを開くまでやり直さなかった
  - 走行記録は「✕」を押したときしか保存していなかった
- 対応：送信のやり直し、走行記録の控え、未送信件数の表示
- 声でメモが動かない原因は未確定。次の走行記録の `start.sr` と `voice` イベントで確認する
- 追記：利用者によると、聞き取り中の表示は出るが、マイクが全く反応しない。手動の「話す」もだめで、通話は普通にできる
  - 原因の候補1：起動時に audioSession を 'ambient' にしていたため、マイクの入力が切られていた。マイクを使う前に 'auto' に戻すよう直した
  - 原因の候補2：iPhoneのChromeの音声認識そのものが動かない
  - 切り分けのため、設定に「マイクと音声認識のテスト」を追加した。結果は送信先の `diag/` に届く

## 2026-11-14（全体の点検）
- 利用者の報告：マイクのテストは「マイク：反応あり／音声認識：aborted」。メモは手入力したが届いていない
- 送信先に届いていたのは、11/10の送信テスト1件だけ（diag も届いていない）→ 走行に使うブラウザに送信先が入っていない可能性が高い
- 実測で分かったルートの問題と対応は、CHANGELOG の同日の項目を参照
- 分かっていないこと：iPhoneのChromeで、アプリ内の音声認識が動くかどうか。次の `diag/` で判断する
